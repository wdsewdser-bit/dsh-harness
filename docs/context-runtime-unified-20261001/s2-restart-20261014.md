# S2 Restart Probe

## Protocol

Use a fresh isolated home `s2-restart-20261014` and the existing S1 host/RPC/
collector drivers. Production plugins remain byte-identical; no staged overlay.
Never start production or change its config, sessions or credentials.

Two serial host runs on port 40125. Initial run: 10 minutes, 32 cumulative
terminal requests. Restart: 10 minutes, 48 cumulative terminal requests. Stop
as soon as the required receipts are collected. Delete isolated credentials at
final cleanup. Preserve both production signatures and plugin hashes.

Phase 1: root spawns one group lead. The child sends one decision marker to its
superior through the canonical send_message tool. Root reads its inbox and
acknowledges that exact wake ID. Capture the durable handled wake and target
member identity, then stop the host.

Phase 2: restart the same home, observe recovery before sending new input.
The exact acknowledged wake must remain handled with no duplicate marker wake.
Prompt the original root to send one action marker to the original member.
Successful cold action requires canonical send receipt and that same child's
durable input and response, not an assistant claim or a newly spawned member.

This scoped probe covers acknowledged-wake restart behavior and inactive-member
action delivery only. It does not close legacy-row migration, timed-out dead
letter retirement, or the unrecorded 41-hour stale-target incident without their
specific counterexamples. Do not report all S2 complete from this probe.

## New Finding: Wake-ID Acknowledgement

Root tool call sequence 44 attempted inbox_ack with the returned
`wake_id: wake:lead:1`. Result: `Error: undefined: wake:lead:1`. Its supported
inbox_id alternative then returned durableHandled=true and status=handled.

Focused source inspection identified a contract mismatch present in production
and staging: `team-v12-runtime.mjs` requires
`inboxAckInputForCaller(...).ok === true`, but the successful helper in
`team-v12-room-wake.mjs` returns acknowledgement arguments without an `ok`
property. Its refusal branch does return ok=false. The existing helper-level
test passes arguments straight to handleWakeBatch and therefore misses the
runtime caller's rejection. No implementation change is made here; a repair
needs a cross-module regression and scoped live wake-ID revalidation. The S2
checks above used inbox-ID acknowledgement and do not close this finding.
