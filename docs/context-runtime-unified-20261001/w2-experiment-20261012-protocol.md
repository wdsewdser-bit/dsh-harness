# W2 对照实验：事先登记的做法和判分

日期：2026-10-12。作者：Claude。这份文件在发任何一个实验请求之前提交。之后只追加“偏离记录”，不改题目和判分。

## 要回答的问题

摘要压缩丢掉的东西，值不值得用 W2 的额外成本去保。判定规则沿用 [w2-continue-decision-20261012.md](w2-continue-decision-20261012.md)“建议的对照实验”一节，原文照抄：

- 压缩组没有丢约束：W2 维持名单模式，不再投入，长期看可以退役。
- 压缩组丢了约束而 W2 组没丢：W2 的定位成立，下一步是把它接成“到硬上限时替代压缩”的自动路径，而不是经济策略。
- 第四组不丢约束且缩减明显更大：普通会话走第四组的形状，W2 只留给 Team 根。

“丢了”在这里的可操作定义：A 类题（见下）答错或答 `NEED_ORIGINAL` 的数量，比不折组多 2 道或以上。差 1 道算没有区别（样本只有 4 道）。

## 四组

起点都是生产根 `session-9afa7cdb-b940-4b7e-8c26-0cb20ad6307a`（会话文件 SHA256 `02524788…`，384 条消息、2,158,609 B）的隔离副本，每组一份新副本，做法同 `window-isolated-refold-20261012`。模型 `opencodego / deepseek-v4.1-flash / high`。

| 组 | 处理 |
|---|---|
| G1 不折 | 副本原样 |
| G2 摘要压缩 | 先执行一次原生压缩命令，再提问 |
| G3 W2 | 先执行一次 `/window fold`（staging 修过的步折叠），再提问 |
| G4 小交接 | 新开一个普通单代理会话。工作区里放 384 条原始消息，每条一个按编号命名的文件，加一份索引。第一条消息是 G2 得到的摘要（标明“非权威”）加一句“原文在 history/ 下按编号存放” |

G1 到 G3：每道题一个回合，同一会话里顺序提问，禁止调用工具。G4：允许读文件和搜索，只在它自己的沙箱工作区里。

这个根在实验之前已经被原生压缩过（对话第 2 条就是一份压缩检查点），所以 G1 不是“从未压缩”，而是“不再做新的缩减”。

## 每组记录的量

- 处理之后、第一道题之前的模型正文字节数和消息数。
- 每个请求的 input、cacheRead、output token，交给适配器的字节数，耗时。
- 处理本身花的请求（G2 的压缩请求）。
- 10 道题的三分类结果。
- G4：每道题用了几次工具、几个请求。

## 上限

- 请求数：G1 10、G2 11、G3 10、G4 24，合计 55，硬上限 64。任何一组超出就停下，不补跑。
- token：用真实大根，不折组每个请求约 65 万 token，四组合计原始 input 约 1400 万，其中大部分应是缓存命中。这超出了决策文档里“每组 input 100 万”的原上限，已在开跑前告知用户。
- 并发 1。每组一个隔离宿主，端口 40124，守护 747 个生产文件，30 分钟自动停。

## 已知的局限（开跑前就知道的）

1. 一个根、一次运行、10 道题。结论只能说“这次观察到什么”。
2. G1 到 G3 禁用工具，所以量不出 W2 组的模型会不会自己去取回原文，只能量出它是否知道自己缺了什么。
3. 题目是我看着原始日志出的，B 类都是行号这类细节。它们对后续工作是否要紧，这次不判断。
4. G4 的摘要来自 G2，所以 G4 不独立于 G2。
5. 同一会话顺序提问，后面的题能看到前面的问答。题目之间的事实互不相干，但不能排除影响。
6. 费用只有适配器回报的 token，没有账单。

## 偏离记录

### 偏离一（2026-10-12 约 06:34 UTC）：不折组不可行，前三组改为离线核对

第 1 组（不折）问完第一道题后，运行时自动执行了一次原生压缩：这一回合结束时上下文是 536,345 / 1,048,576 token（51.1%），超过主动压缩的 50% 线。也就是说在这个运行时里，这个根“不折”的状态最多维持一个回合。随后运行时注入“压缩恢复”消息，模型在回答完第二道题之后无视题目里的“禁止调用工具”，开始调用工具查看任务板和真实工作区。我立即停了宿主。它一共做了 7 次调用，全部只读（`team_task_get`、`list_agents`、`glob`、两次 `team_v12` 查询、`team_task_list`、`pwsh Get-ChildItem`）；真实工作区和生产目录在此期间没有任何文件变化。

因此：

- 不再对活的 Team 根逐题提问。G1 到 G3 改为离线核对“答案是否还在模型能看到的上下文里”。答案不在上下文里，模型就不可能答对（只能说需要原文或者编造）；答案在，不保证模型一定找得到。所以离线核对给出的是每组的上限。
- G2 不是我手动触发的压缩，而是运行时自动做的那一次。它之前多了一个问答回合（C1）。
- 原方案的请求上限没有用完：实验共完成 5 个请求（1 个不折的问答、1 个自动压缩、1 个压缩后的问答、2 个压缩恢复步骤），另有 2 个在停宿主时被中断。
