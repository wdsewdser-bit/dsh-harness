# DSH 整体重构简报（2026-10-26）

依据四份盘点：[01 代码](01-code-inventory.md) · [02 文档/功能/决策](02-docs-features-decisions.md) · [03 ctx-mod/ptc 背景](03-ctx-ptc-background.md) · [04 上游差异](04-upstream-diff.md)。
本文是主会话的综合判断和建议，01/02/04 由子代理产出，关键结论已抽查（pre-step 钩子已在新版 `dsh-agent-loop/lib/index.js:904-909` 亲自核对）。

## 1. 现状一句话
自研部分约 5.1 万行（web 现役闭包 96 文件），加 10 个 pnpm 补丁和 staging 对 22 个上游包的 60 处原地覆盖；web / headless / teamtest 三套环境不等价；79 轮缺陷可归成 11 个根因族，"已修"大多没真机复验；480 个文档里只有 3 处可当权威。

## 2. 最关键的几条事实（决定重构方向）
1. **上下文问题不是上游缺能力，是我们的设计错了。** 新旧两版 agent-loop 都在每一步之前派发 `agent/pre-step`，上游 compaction-basic 就是在这里按 75% 阈值压缩的。W1/W2/W3 偏偏绑在"回合结束/空闲"上，真实根成员一个回合 187 步不结束，所以一次都没执行；另外经济层缺 cache-write 计量，判 unknown 也会拦下。→ 重写时直接挂 pre-step，按 token 触发，以"已闭合步骤"为折叠单位。
2. **Agent Team 上游也有（旧版就有），但不能直接替代。** 上游是 profile bundle 开关，消息走目标 Agent inbox/Steer；我们的分层指挥链、room、写域约束、exact-SHA 合并、可靠投递、wait 票据它都没有。→ 我们的 Team 应做成**独立 profile、默认不启用**，建在上游 team 包的接口上，只补它没有的。
3. **"升级"不能靠覆盖旧包。** 旧安装里混着我们的 nativeSessionBridge、定制压缩保留参数、goal 完成门禁等私有改动，新版没有。→ 先把这些语义从旧包里抽成独立插件，再在干净的 0.2.1 上装回去；以后不再原地改上游包。
4. **大工具输出在入口截断并落盘**（03 的建议），可能比折叠更能压住上下文增长，成本也最低。

## 3. 建议的目标架构
- **底座**：干净安装上游 0.2.1-rc.x（之后跟版），零原地补丁；所有自研能力都是标准 cordis 插件，按 profile 组合。
- **profile**：`default`（不带 Team，日常单代理用）、`team`（Agent Team 模式）、`headless` 与 web 同源生成，不再手工维护两份。
- **上下文插件（一个）**：pre-step 上三层——①工具输出入口截断落盘；②≥20 万时折叠已闭合步骤（调用与结果配对、保护最近 N 步、reasoning 原样）；③上游 75% 压缩兜底。保留已定约束：20 万以下不折叠、75% 硬上限、命中:未命中 1:50 的经济判断（计量缺项时按保守值，不能判 unknown 就整体失效）。
- **Team 核心**：单一状态存储 + 事务写（一个写者、版本号/CAS），专门对着 11 个缺陷根因族设计：不允许旧快照写回、投递必须有回执、状态机每个状态都有出口。调度、room、看板、goal driver、可靠投递拆成清晰模块，接口文档化。
- **UI**：基于上游 `dsh-client-ui-*` 模块化扩展，主界面加 Team 面板（成员、看板、room、上下文用量、折叠记录），不改上游组件源码。
- **文档**：6 层新结构（见 02 §4.4）：总览 / 架构 / 各模块规格 / 运维手册 / 决策记录 / 归档；旧文档整体移入 archive，不再维护。

## 4. 建议分期
| 期 | 内容 | 验收 |
|---|---|---|
| P0 | 冻结基线：生产全量备份；git 提交当前状态（先扫密钥） | 备份可恢复；仓库无密钥 |
| P1 | 新隔离目录干净装 0.2.1 + profile 骨架 + 从旧包抽出私有语义清单 | 空 profile 能启动；default 模式与上游行为一致 |
| P2 | 上下文插件 + **真实探针**（回合中改写历史，DeepSeek 与 Responses 网关是否接受、缓存是否失效） | 探针通过才继续②；模拟长回合上下文受控 |
| P3 | Team 核心重写（存储、调度、room、投递、看板、goal） | 移植旧测试中仍有意义的用例；11 族缺陷各有回归测试 |
| P4 | UI | 浏览器视觉验收 |
| P5 | 数据迁移与切换：旧会话/看板数据迁移或只读保留；生产切换（需你确认） | 真机长测 |
