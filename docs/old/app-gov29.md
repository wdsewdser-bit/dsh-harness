
**30. 判据的检索模式必须能匹配被测文本的「字面形态」（含标记字符）。** 实测（tier 0 · 同一形态第 2 次）：我为 `task-28` 写的判据③是 `grep -c 'dependency 的判定粒度'` ⇒ **0 命中**，而**交付正确** —— 被测文本是 `` `dependency` 的判定粒度 ``（**标识符带反引号**）⇒ **我的模式缺了那对反引号，因此不可能匹配**。⇒ **判据「0 命中」不等于「未交付」。**
   · 与 §5.14-19（形成判据前必须检索已登记口径）**同族但更细**：那条防**与已登记口径冲突**，这条防**模式与文本形态不符**。
   · ⇒ 纪律：**凡用检索模式断言「存在 / 不存在」，必须先把该模式在同一文本上跑一次并给出命中数**（§5.14-16：命中数必须与模式原文同屏）。

**31. 卡面内的「示例」与「正文要求」必须同向 —— 否则成员被迫二选一，且会选最坏的那个解。** 实测（lead-world 第 138 条 · t60）：卡面 c2 的**示例**含「失真原因：该块被重写致行号漂移」，而正文写「**成因不断言**」+「**非** t56 所致」⇒ **两条要求互斥**，成员**被迫二选一**，而它选了「**发明一个具体成因**」= **最坏解**（该成因随后被判 major）。⇒ **根因在出卡方，不在成员。**
   · 与「两个不可同时满足的判据不是判据」（第 114 / 128 条）**同族**：本条是它在**同一张卡的示例与正文之间**的形态。
   · ⇒ 纪律：**示例是判据的一部分**；改正文要求时**必须同步检查示例**，反之亦然。
