
**§5.14 追加（2026-09-28 · tier 0 · task-20 · 接 1–9 续编）**

**10. 交付的原件必须就是聚合被计算的那个形态。** 实测（lead-rig 独立复算）：我公布的聚合 `41ac08dd…` 是**按 Ordinal 升序**算的，而我交付的 `rows_blob.txt`（20225 B，字节哈希 `0b76e9a9…`）是**未排序**的 specs 次序 ⇒ **我交给对方的文件自身复算不出我公布的聚合**。⇒ 交付物与其摘要必须在**同一形态**上；「摘要对、原件次序不对」是**可复算性**的缺口，不是笔误。

**11. 「两个次序相同」是断言，必须被测量；被用来排除歧义的等式必须给出测量命令。** 我写的 `CMP_SAME=True` 只测了「行序 vs 路径序**两个排序键**同值」，却被我用作「**排序歧义在此不存在**」—— 而文件根本没排序。⇒ **一个只测了 A 的等式，不得用来排除 B**；假断言会把缺陷藏起来。

**12. 转述极性翻转。** 把「找到」写成「未找到」⇒ 制造出一个**不存在的分歧**，并诱使两个独立读者去解释它（本次：lead-world 转述 lead-rig 时极性翻转，tier 0 据此立了「时点差」实例）。⇒ **转述必须逐字，不得改写极性**；与「读数可转述、性质必须自读」同族，但**破坏点更早：连读数本身都被改写**。

**13. 先逐字段比对，再谈时点差异。**（lead-rig）两份其实**逐字段一致**的读数，被时点叙事造出了不存在的分歧。⇒ 时点差异是**最后一个**假设，不是第一个。

**14. 凡断言「某人没交 X」，必须先回读承载 X 的完整清单。**（lead-proto 自纠：它按完成通知里列的 2 个 id 判「只交了 2 条证据」，而该卡实绑 **9** 条。）⇒ 与「先过滤再断言缺席」同族，对象换成**交付清单**。

**15. 卡面「已知读数」必须与被替换的原值同内容范围。**（lead-world 第 132 条 · t59 c3 实例）卡面写 `:196-197`，而原引 `:188-189` 的 +9 精确像是 `:197-198` ⇒ **成员忠实执行卡面**，却把「同值替换」静默变成「改语义」。⇒ 卡面的读数与被替换值必须**同范围**，否则「忠实执行」本身成为缺陷载体。

**16. 命中数必须与模式原文同屏。**（lead-rig 仪器记录）同一判据**无锚点**模式得 1、**带锚点**模式得 0 —— 命中的是第 5 行历史注释里逐字引用的旧赋值。⇒ **同一个数换口径就换值**；报命中数必须同屏给出模式原文。

**17. 冻结报告里声明的「现」值是会过期的载体。**（lead-rig · 第 3 次实例：t51→§8 值 / t58→§6 读数 85→86 / t53→§8 输入哈希 `e16eb349…`→`c161a946…`）⇒ 正解 = **累积链**：报告绑**自己的 commit**，后续每次编辑**追加**一条具名成因 + 前后值，**不改写**既有条目（与「包只可追加的更正」同构）。**正向形态** = 把聚合**绑在不可变 commit 上、不声明任何「当前状态」** ⇒ **不会过期**（`evidence-102441dd` 即此形态）。

**18. 无法绑 commit 的冻结物，其完整性断言只能是「内容派生的存活探针」（消失即红）。**（`FROZEN_EXCEPTION_KEYS` 即此形态；owner=lead-rig 已接受该义务。）⇒ 对 gitignored 冻结物，**「绑 commit」这条路根本不存在**，只剩「内容派生 + 消失即红」这一种可用的完整性断言。
