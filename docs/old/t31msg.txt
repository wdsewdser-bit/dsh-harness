task-31: §5.14 补 commits 元素形状冻结 + §5.14-33（可推得 != 已声明 + 载体五项清单）
        + B-61 补充六（完整机制规范表述）

- commits 元素形状冻结为 {task, sha}；裸字符串不合格；若要允许两种必须包内显式声明元素形状。
  一般化：冻结一个容器，还须冻结它的元素形状（与「冻结一个对象还须冻结位置与嵌套」同一缺口两个层级）。
- §5.14-33：「可推得」不等于「已声明」—— 猜错基准的消费者会得到不同的值，且分不清是载体错还是自己读错。
  标准五项清单：路径基准 / 排序键 / 分隔符 / 行尾 / 判别长度（或编码），逐项显式。
- B-61 补充六（权威表述）：可求值条件（dependency）按锚点卡 status 求值并被尊重；
  不可求值条件（background/manual）被立即置 resolved 并写下假串 auto:condition-cleared。
  补充三/四/五不撤销，但不得被单独引用为完整机制。
