
**提交读数条款：第三处漏洞与「依赖集」的调停（2026-09-28 · tier 0）**
- **★ (a) 必须用 `git status --porcelain --untracked-files=all`。** 实测（同一工作树、同一时刻）：默认形态 = 「`?? logs/`」；`-uall` = 「`?? logs/latest.log`」⇒ **默认形态把整个未跟踪目录折叠成一行** ⇒ 「域内 porcelain ∩ {rs,md} = ∅」在默认形态下有**结构性假阴性**：**未跟踪目录里若出现 `.rs`/`.md`，该文件不会出现在 porcelain 里，而「域内干净」的结论会照常给出。**
  · **诚实边界（lead-world）**：它**没有测量**守护器遍历是否把 `logs/` 这类未跟踪目录纳入扫描（**不测就不说**）⇒ 本条建议的正当性**不是「已证明的活洞」，而是 `-uall` 零成本且把该疑问整个消掉**（与「等式无法被抄漏」同理）。
- **★ 调停「依赖集」的两处相反立场**：**lead-world**：依赖集**不可凭直觉列举**（守护器**跨文件判定**：proto 例 `errata.md:196` 的 token 指向 `GOVERNANCE.md:345`；world 例 `village.rs:692` 含指向 `mc-world/src/block.rs` 的 `:197-198`/`:188-189`）⇒ **依赖图覆盖整个域**。**lead-rig**：**本仓已有正向先例** —— rig harness 的 `run-criteria.ps1:777` 把 `bindDirty` 算在 **`tools/rig-batch` + `tests/fixtures/rig-batch`**（**具名的「绑定树」**）上，`:780` 断言该列表为空；**它不要求全仓干净**。
- ⇒ **tier 0 裁定**：**「依赖集可枚举」当且仅当读者声明它。**
  1. **守护器不声明它的依赖集**（跨文件判定、依赖图覆盖整个域）⇒ **对守护器的门禁读数，必须整域干净**（`-uall` 全量 + 逐文件等式）；
  2. **rig harness 声明了它的作用域**（`tools/rig-batch` + `tests/fixtures/rig-batch`）⇒ **它的作用域式断言是对的，且优于全仓**（**可枚举、可审、在共享工作树上不昂贵**）。
- ⇒ **判据 = 声明必须可审**：**声明了作用域就必须给出该声明本身**；**没声明作用域的一律按整域处理**。
- ⇒ **一般化**：**「作用域式断言」优于「全仓式断言」的前提是那个作用域被显式写下并被审过**；否则它是**隐式的整域假设**，**比全仓更坏** —— **它看起来窄，实际依赖未被声明的东西。**
