## 核心约定

- `info` 保持静默，`action/decision` 是定向唤醒；完成/依赖解除是系统事件，不要求模型伪造阻塞决策。
- 自动接续只执行已批准、已分配且 scope/lease/依赖条件成立的任务；不自动创建成员、改 owner 或扩大权限。
- 每个等待保存任务、原因、解除条件、责任人、最近有效进展与下一检查时间。超时不能只变成一个没人消费的终态。
- Room 等待仅约束该轮发言；没有开放轮次的 stop 不能掩盖其他已批准工作。依赖完整的交付批次可送审，不等待无关慢组。
- 唤醒、注入、处理是不同状态。消息成功写进上下文只确认 injected，完成动作后才能 handled。
- 当前任务及要求/决定按版本发差量；不把整个收件箱或整个状态 JSON 输出给模型。
- PTC 串行依赖变更，独立读取可并行；每个子调用有回执，后半失败不能当作前半回滚。
- 存储迁移不清历史，不修改原生 session journal；旧格式双读、记录迁移版本和历史位置，可回滚。
- 模型路由沿用已配置默认供应商，不新增未经用户要求的路由。Reducer/经济压缩需分开做有界质量验证；不等待固定天数，不为验收启动大工程。

2. 并行实施不共享文件的基础模块；根代理负责桥接入口、集成、迁移与验收。
3. 先完成 A–D、F，再接 E；G–I 独立开发后接入。J/K 使用稳定服务接口。
4. 聚焦回归、真实官方工具 envelope 测试、多进程 fixture、旧会话 dry-run 和兼容回读。
5. 独立审查调度幂等性、权限、消息确认和迁移一致性；修完新增发现。
6. 独立新测试会话进行短 PTC 多组接力，覆盖依赖、一次失败恢复、Room、记忆恢复；不继续用户主项目。
