docs: 新条款「归属判定必须以对象自身的自述为准；层级标签不是组名；自称未验证的设计稿不是权威」（tier 0 认错）

- 实证：一个工具的归属在「分层」与「作者」之间有争议。tier 0 据布局文档里的层级标签（L3）判归 B 组，并据此解除了该组原有的写入约束 —— 但没读该工具自己的自述。实测三处（README 首行、src/main.rs 首行与 usage 常量）都写「L3 …（G-WORLD · M0/W0-5）」⇒ L3 是「差分层级」标签，G-WORLD 才是所有者；且那份布局文档自称「本布局是设计稿·未验证」。
- 纪律：归属判定先读「对象自身的自述」（README / 模块头 / usage），再看历史作者；层级标签（L0/L1/L2/L3）不得当作组名；自称「未验证 / 设计稿」的文档不是权威。
- tier 0 认错：又一次「未读全证据就下判定」，且错在解除一条既有约束上 —— 解除比新增更危险（它把两方放到了同一路径上）。⇒ 解除约束前必须先把归属证据读全。
- 配套（本次的缓解）：两条裁定在几十分钟内被撤回，因为两方都没有抢先动手（一方在等裁定，另一方按标准链推进）⇒「裁定未落定前不动手」是本次未造成重复修复的唯一原因。
- 实测零损失：撤回时 interrupt_agent(rig-trace) 返回 previousStatus=inactive，且 git status --porcelain -- tools/chunk-hash 为空 ⇒ 该路径零写入。
