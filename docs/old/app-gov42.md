
**§5.14 裁定：`carrier_field` 必须是可解引用的裸键（2026-09-28 · verifier 请示 · tier 0 裁定）**
- **事实**：world 组（含 t61，**7 包同形**）把 `carrier_field` 写成**载体描述**（`village.rs:692` / `全仓 block\.rs:[0-9]+` / `cargo test 门禁`），而被引 evidence 行的键集 = `{evidenceId, taskId, commitSha, requirementId, kind, command, expected, actual, output, paths, classification, status, createdAt}` ⇒ **`row[carrier_field]` 实测 `undefined` 6/6**，与 `GOVERNANCE.md:623` 冲突。
- **裁定：保持条款（裸键），改写法。** 理由：该字段的**存在理由**就是让消费者**能解引用**「哪个字段承载逐字」；**载体描述不可解引用 ⇒ 它使该字段失去功能**。
- ⇒ **不得把条款限缩为「可机检者优先」** —— 那等于**把不可解引用的形态留在可选集里**（§5.14「只给白名单等于把错的形态留在可选集里」）。
- **可机检判据（新增）**：**`row[carrier_field] !== undefined` 必须成立**；不成立即缺陷 —— **不得**以「描述也能看懂」豁免。
- **不追溯**：**7 个已提交的 world 包不重开**（沿用 `:803` 先例：**记纪律、不重开**）；**自本裁定起**，新包的 `carrier_field` 必须是裸键。
- ⇒ **与 `:803` 的关系**：`:803` 的处置是「记纪律、不重开」，**不是「条款错」**；本条与它一致 —— **都是「条款保持、写法改、历史不动」**。

**§5.14-34 配套 补（2026-09-28 · verifier 实测 · tier 0 采纳）**
- **快照声明必须精确到「谓词」，不能只到域。** 实测：t61 自己的修改使 `block\.rs:[0-9]+` 的**内容处由 15 变 16**，而**行数 11 不变** ⇒ **「软形态」在同一行内追加 token 时也会发生**。
- ⇒ 「**模式 + 域（含 revision）+ 谓词（行数 / 内容处 / 含前缀处）**」三件套里，**谓词是承重项**：**只声明域而不声明谓词，读数仍不可复算。**
