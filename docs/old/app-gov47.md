**位置键的完整机制（2026-09-28 · lead-world 实测 · tier 0 采纳）**
- **例外键形状 = `path:line|token`** ⇒ **键豁免的是 (文件, 行号, token) 三元组，不是 (文件, token)**。三个后果：
  1. **行内编辑移动列号** —— **去列号已解决**；
  2. **把同一 token 写到同一文件的另一行 ⇒ 新键、未登记、新红灯**（本次 `:1368` 的两条）；
  3. **在上方插入 / 删除行使被豁免行位移 ⇒ 旧键 `present=false` ⇒ dead 键**（§5.14-35 的原始现象）。
- ⇒ **推论：「记录该机制」这个动作本身必然在新行号上重写同一 token ⇒ 必然新增未登记项。**
- ⇒ **四次自指污染的完整机制**（errata(t52) → `:1297`(task-36) → `:1355`(task-42) → `:1368`(task-43)）：**不是作者不谨慎，而是「位置键 + 逐字引用」的结构性后果。**
