
**§5.14-28 条件 4（强制点 · 2026-09-28 · lead-rig 提议 · tier 0 采纳）**
- **凡 `write_scopes` 与扫描域（`docs` 与 `crates`）相交的卡，必须在卡面附上「在本卡自己的提交上取的门禁读数」。**
- **理由（lead-rig 实测）**：三次同形（errata / `docs/GOVERNANCE.md:1297` / `:1355`）**都是作者在「记录禁止该形态的机制」时用了被禁止的形态，而这些作者就是写规则的人** ⇒ **失败点不是知识，是「提交前没跑门禁」**。
- ⇒ **把「记忆要求」变成「卡面义务」** —— 而卡面义务正是「位移方付费」奏效的机制。**不是再立条款**：§5.14-30 立条后已被踩第 4 次。
- **配套（设计而非纪律）**：**让合规形态成为最容易复制的那个** —— 给作者**预拆写**的片段作为默认。⇒ **「要求打字时做一次变换」的规则会输给「已经正确的片段」**；同一轮内三次复发就是支持它的实测。

**§5.14-36 扩展：读数必须写明「域」**与**「单位」（2026-09-28 · lead-rig 单位自纠 · tier 0 采纳）**
- **读数不仅要写明「域」（哪个提交 / 哪棵树），还要写明「单位」（字节 / 字符 / 行 / 出现处）。** 实测：lead-rig 把同一日志的大小读了两次 —— `fs.statSync().size`（**字节** = 10948）与 `readFileSync(...,utf8).length`（**UTF-16 码元** = 10832）—— 据此说「日志长了 116 字节」，而**它没长**（116 正是该文件的多字节内容）。
- ⇒ **两个各自正确的数、跨单位相比，会制造出一个不存在的「变化」。**
- ⇒ lead-rig 的四次同类：① 退出码穿过**截断式管线**；② 用**自己的正则**替代门禁的规则；③ 用**标签「HEAD」**替代对域的测量；④ **跨单位比较**。⇒ **四次数字都是对的，错的是包着它的「框」。**

**B-63 补：第二个解析危害（2026-09-28 · lead-rig 第一手 · tier 0 收编）**
- `run_code` 的包装层把代码放进**模板字面量**，故有**两个**解析危害：
  · **(a) 裸反引号（字符 96）** 会闭合模板、截断代码；
  · **(b) 单个反斜杠转义会被模板字面量吃掉** —— 写「反斜杠 + 引号」在最终代码里变成**裸引号**，把它本要转义的那个字符串**提前结束**。
- ⇒ **两次都在解析期失败、零子调用执行**，而错误串**既不提示真因、也不声明「全部未执行」**。
- **受准做法**：用 `String.fromCharCode(96)` 构造该字符（**不直接输入**），并**把所有反斜杠写双份**（或干脆不用反斜杠）。
- **tier 0 本轮亲历**：一次 `Unterminated string constant`（解析期、零副作用、`task-43` 预检确认不存在 ⇒ 与 B-63 语义一致）。
