
**提交读数规则的补强（2026-09-28 · lead-world 实测 · tier 0 采纳）**
- **hash 等式应覆盖「读数所依赖的每一个扫描域文件」，不只是 guard。** 实测：lead-world 有一次读数 **guard 等式成立但文档 dirty** ⇒ 那只能算「**提交守卫 + 工作树文档**」读数，**不是提交读数**。
- ⇒ **完整形态**：一次读数只有在**同一次调用内**，对**读数所依赖的每个扫描域文件**都满足 `git hash-object <f>` == `git rev-parse HEAD:<f>`，才算「**提交读数**」；否则必须写明**哪一部分是提交的、哪一部分是工作树的**。
- ⇒ 与 §5.14-36 合并：**域不只包含「哪个提交」，还包含「每个依赖文件的哈希是否等于其提交版」。**
